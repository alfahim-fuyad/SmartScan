About the project

Classical image processing, applied end to end

Smart Document Scanner is a course project for CSE 438 — Digital Image Processing Lab. It demonstrates how far traditional techniques — no machine learning, no OCR, no external AI services — can go toward turning an ordinary photograph into a clean, readable digital scan.

The pipeline

Every scan follows the same deterministic path. The uploaded photo is safely decoded and validated, then a working copy is converted to grayscale and smoothed with a Gaussian kernel so that Canny edge detection concentrates on real boundaries. External contours are extracted, sorted by area and simplified with polygon approximation until a plausible four-corner document outline appears.

Those corners drive a perspective transformation (cv2.getPerspectiveTransform + cv2.warpPerspective) that re-projects the tilted paper onto a straight rectangle. Enhancement operators — brightness/contrast scaling, unsharp masking, non-local-means or bilateral denoising, and CLAHE — are applied to the warped page, and the chosen filter (grayscale, Otsu black & white with morphological cleanup, adaptive threshold, or enhanced color) finishes the job. Exports re-run this exact pipeline at full resolution.

Engineering choices

The backend is Django 5.2 LTS with a strict separation between views and reusable OpenCV service modules, which keeps every technique unit-testable. Uploads are validated on the server — magic bytes, Pillow verification, a full OpenCV decode, and hard limits on size and pixel count — and stored under generated filenames, so client-supplied names never touch the filesystem. Scans are private to the browser session that created them; logging in optionally attaches history to an account.

Static assets ship through WhiteNoise with compression, the app is served by Gunicorn, and metadata lives in PostgreSQL (Neon in production) while image binaries stay on disk — never inside database rows.

What this project is not

Detection is heuristic: unusual lighting, low contrast against the background, or cropped-away edges can prevent automatic boundary detection. In those cases the UI explains what happened and offers manual corner adjustment or full-image fallback. Quality checks (blur, brightness, contrast, resolution) are advisory heuristics, not guarantees. No PDF input or OCR is supported, and no AI models are used anywhere.

Technology credits

  • Python 3.12 — implementation language
  • Django 5.2 LTS — web framework, ORM, auth, sessions
  • OpenCV — edges, contours, transforms, filters
  • NumPy — array processing
  • Pillow — image verification and formats
  • ReportLab — PDF generation
  • PostgreSQL + Neon — production database
  • WhiteNoise + Gunicorn + Render — static files and hosting
